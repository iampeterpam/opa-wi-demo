1GitHub OIDC Token i
The CI/CD runner requests a signed JWT directly from GitHub's OIDC endpoint — no stored secret needed. This token cryptographically proves the job's identity: which repository, branch, and workflow triggered it. OPA validates this token against the Workload Connection's JWKS URL and required claims before issuing any access.

        2OPA Access Token
        
          i
          
After validating the GitHub OIDC token, OPA issues its own short-lived access token (default TTL: 300s). This token represents the workload's authenticated identity within OPA and is used to request brokered SSH access. It cannot be refreshed — the workload must re-authenticate from scratch when it expires.

        3SSH Connection
        
          i
          
Using the OPA access token, the sft CLI requests a just-in-time SSH certificate and ephemeral account on the target server. The account (wl_ prefixed) is created at job start and torn down immediately on completion. No standing SSH keys or persistent accounts are used at any point.
